# dndbuilder

An open-source, cross-platform (Linux and Windows) character builder for D&D 5th edition, compatible with
**[Aurora Builder](https://aurorabuilder.com/)** content files.

Aurora was a well-loved Windows-only builder whose development stopped around 2020. Its data format lives on in the
community-maintained [AuroraLegacy/elements](https://github.com/AuroraLegacy/elements) repository. dndbuilder is a
from-scratch reimplementation of the rules engine, with a modern UI that you can keep developing:

* loads Aurora `.xml` element files and `.index` content indexes, including updates from the AuroraLegacy repository;
* builds characters with races, classes, multiclassing, backgrounds, feats, ASIs, spells and equipment, driven entirely
  by content rules;
* supports the 2024 rules' backgrounds with imported 2024 content: Origin feats, background ability score increases
  (+2/+1 or +1/+1/+1) and feat categories;
* computes the full sheet (abilities, saves, skills, AC, HP, speeds, proficiencies, features, spellcasting) with
  breakdowns showing where each number comes from;
* imports Aurora `.dnd5e` character files;
* includes a searchable compendium of everything loaded;
* runs as a native desktop app (Tauri) on Linux and Windows. The UI also runs in a plain browser for development.

> **About content.** The app ships with the rules plumbing (`content/core`) and the
> [System Reference Document 5.1](https://dnd.wizards.com/resources/systems-reference-document) (`content/srd`), which
> is licensed under [CC-BY-4.0](https://creativecommons.org/licenses/by/4.0/): nine races, the twelve classes with one
> subclass each, the Acolyte background, equipment and 315 spells, so it works out of the box. It does not ship any other
> copyrighted game content. Load content you own or that is openly licensed, from an index URL or your own XML files.
> SRD element ids match the community content, so characters stay valid when you add more sources.

## Repository layout

| Path | What |
|---|---|
| `packages/engine` | TypeScript rules engine: XML parser, content registry, expression language, resolver, stat calculator, sheet builder, Aurora import. No UI or platform dependencies. |
| `apps/desktop` | React UI and Tauri v2 desktop shell (`src-tauri`). |
| `content/core` | Built-in system content, generated by `scripts/generate-core.mjs`. |
| `content/srd` | Built-in SRD 5.1 content (CC-BY-4.0), generated by `scripts/generate-srd.mjs` from data in `scripts/srd/`. |
| `docs/aurora-format.md` | Behaviour reference for the content format: read this before changing the engine. |

## Getting started

Requirements: Node.js 20+; for the desktop build, Rust (stable) and the
[Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) (on Debian/Ubuntu: `libwebkit2gtk-4.1-dev`,
`librsvg2-dev`, `patchelf`; on Windows: WebView2, which ships with Windows 10/11).

```sh
npm install
npm test                 # engine unit + integration tests
npm run dev              # UI in the browser at http://localhost:1420
npm run tauri dev        # desktop app with hot reload
npm run tauri build      # installers in apps/desktop/src-tauri/target/release/bundle
```

### Integration tests with community content

The engine's integration tests run against a local checkout of the community content when it is present:

```sh
git clone --depth 1 https://github.com/AuroraLegacy/elements.git fixtures/external/aurora-legacy
npm test
```

(`fixtures/external` is git-ignored. Set `AURORA_LEGACY_DIR` to use another path.)

## Using the app

1. **Content** tab → *Download* (prefilled with the AuroraLegacy index limited to the 2024 rules; *Aurora Legacy: everything* switches to the full one) or *Import XML files…*. In the desktop app
   you can also drop XML files into `Documents/dndbuilder/custom` (like Aurora's custom folder) and press *Rescan*.
2. **Characters** → *New character* (or *Import…* an Aurora `.dnd5e` file).
3. **Build**: choose class and levels, ability scores, and work through the choices. Red dots mark open choices.
   Click the portrait square next to the name to pick a portrait from the built-in gallery or from an image file.
   The portrait is saved inside the character and shows on the character list, the sheet and the PDF; portraits in
   imported Aurora files come along too.
4. **Equipment**: add items and equip armor, shields and weapons. AC updates automatically.
5. **Spells**: prepare spells for each spellcasting class; slots, save DC and attack bonus are calculated for you.
6. **Sheet**: the finished character. *Export PDF* writes a multi-page character sheet (US Letter or A4) with
   spellcasting, companion and background pages.
7. **Party** (for DMs): group saved characters into parties. The party view lines up AC, HP, initiative, speed,
   passive Perception/Insight/Investigation, spell save DCs, senses and coin for every member, adds up the
   encounter XP budget (DMG 2014 thresholds), and shows who speaks which language, who is best at each skill,
   saving throw coverage and who needs light. Edits to a character show up in its parties automatically.

Characters autosave locally. Use *Export* to get a portable `.json` file.

**Units:** the *ft / m* switch in the top bar shows distances and weights in meters and kilograms everywhere
(sheet, descriptions, compendium, PDF export). It uses the convention of the game's metric editions, which keeps the
5-foot grid: 5 ft = 1.5 m, 1 mile = 1.5 km, 1 inch = 2.5 cm, 1 lb = 0.5 kg. Content files stay in feet and pounds.

## 2024-only community index

`content/indexes/aurora-legacy-2024.index` is the [AuroraLegacy](https://github.com/AuroraLegacy/elements) index reduced
to the 2024 rules (D&D 5.5e):

* the edition-neutral `internal.xml` and `ALE.xml`;
* the released 2024 books: the 2024 Player's Handbook, the 2024 Dungeon Master's Guide and the 2025 Monster Manual;
* 2024 books still waiting in open AuroraLegacy pull requests (Astarion's Book of Hungers, Netheril's Fall, Heroes of
  Faerûn, Adventures in Faerûn, Lorwyn: First Light, Eberron: Forge of the Artificer, Arcana Unleashed and Deadfall,
  Ravenloft: The Horrors Within), linked at each pull request's latest commit, together with the changes those pull
  requests make to the shared files. They haven't been reviewed by the AuroraLegacy team yet.

The index contains links only; the files stay hosted by AuroraLegacy. The app ships a copy, so it installs even when this
repository isn't public. Files load in the order the index lists them, so a pull request's version of a shared element
replaces the released one.

`scripts/generate-2024-index.mjs` rebuilds it with git (no GitHub API needed). It recognizes 2024 books by their source
(5.5e, release date) or title, takes the pull requests listed in `PULL_REQUESTS` (dropping them once merged), and
reports 2024 books AuroraLegacy doesn't have yet. Rerun it when AuroraLegacy adds books, merges a pull request, or a pull
request gets new commits:

```sh
node scripts/generate-2024-index.mjs                 # clones AuroraLegacy into a temporary folder
node scripts/generate-2024-index.mjs --local <dir>   # uses an existing git checkout of AuroraLegacy/elements
```

## Writing and converting content

Check your own XML (homebrew, or books you own converted for personal use) before loading it:

```sh
npm run validate-content -- ~/Documents/dndbuilder/custom/my-homebrew
npm run validate-content -- my-files/ --base other-pack/   # content that builds on another pack
```

The validator loads the bundled core and SRD content, then your files, and reports per file and line: broken XML,
grants and choices that point at nothing, malformed requirements, missing spell or class data, and elements nothing
can reach. It also puts every class, subclass, race, subrace and background on a test character (classes up to level
20) with every choice made, so a clean run means the content is playable. Options: `--no-srd`, `--no-build`,
`--strict` (fail on warnings), `--json`.

**Converting a PDF with Claude Code:** the repository ships a project skill,
[`.claude/skills/convert-pdf`](.claude/skills/convert-pdf/SKILL.md). Run `claude` in the repository and ask, for
example, *"convert the spells on pages 211–289 of ~/books/phb.pdf"*. Claude reads the pages, writes the XML into your
custom folder (outside the repository), runs the validator until it is clean, and checks the numbers against the page.
Converted books are for your own use: don't commit them or share them.

### Portable Windows version

Every release also ships `dndbuilder_X.Y.Z_x64_portable.exe`: a single file that runs without installing anything
(it needs the WebView2 runtime, which Windows 10 and 11 already include). Put it in any folder you can write to, for
example on a USB stick, and run it. It keeps all of its data in a `dndbuilder-data` folder next to the exe: saved
characters and settings in `webview`, your own XML content in `custom`. Move or copy the exe together with that
folder to take everything with you.

Portable mode is on whenever the exe's file name contains `portable`, or a file called `portable` or `portable.txt`
sits next to it. If the folder isn't writable the app falls back to the normal locations (your Documents and AppData
folders), like the installed version. Pull-request builds publish the same exe as the `dndbuilder-Windows-portable`
CI artifact.

## Releasing

Releases are built by GitHub Actions (`.github/workflows/release.yml`) for Linux (`.deb`, `.rpm`, `.AppImage`) and
Windows (`.msi`, `-setup.exe`, and a portable `_portable.exe`), with a `SHA256SUMS.txt` and release notes generated from merged pull requests (grouped by
label, see `.github/release.yml`).

* **One click:** Actions → *Release* → *Run workflow* on `main`, and enter the version (`0.2.0`, or `0.2.0-1` for a
  pre-release). The workflow runs the tests, bumps every version file, commits `Release v0.2.0`, tags it, builds the
  installers and publishes the release. If `main` is branch-protected, allow GitHub Actions to push to it, or use the
  second option.
* **From a tag:** `node scripts/version.mjs 0.2.0`, commit, then `git tag v0.2.0 && git push origin v0.2.0`. The
  workflow checks that every version file matches the tag before building.

`node scripts/version.mjs` prints the current version and fails if any file is out of sync. If a build fails, the
draft release is deleted; delete the tag (and revert the version commit) before retrying the same version.
